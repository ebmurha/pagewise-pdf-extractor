# Release v0.3.0

Backward-compatible extraction quality release for `pagewise-pdf-extractor`.

## Summary

This release improves routing and OCR for PDFs that contain misleading embedded text, two logical pages in one physical page, damaged word spacing, or layout-only tables.

Clean born-digital prose still uses fast embedded-text extraction. Pages that fail structural quality checks are rendered into image-only PDFs and processed with Marker OCR.

## Highlights

- Detects corrupt Type3 glyph streams and other unreliable embedded text.
- Detects abnormal PDF word spacing.
- Routes table-heavy pages to visual OCR/layout extraction.
- Renders Marker input at a configurable 350 DPI.
- Detects and splits two-up scans into left and right logical pages.
- Preserves logical-page source coordinates and split confidence as layout artifacts.
- Prevents corrupt source text layers from influencing Marker.
- Avoids duplicate table rendering in page Markdown.

## Configuration

New `ExtractionConfig` fields:

- `validate_text_quality=True`
- `prefer_visual_tables=True`
- `detect_two_up=True`
- `marker_render_dpi=350`

Equivalent CLI controls:

- `--no-text-quality-check`
- `--no-visual-tables`
- `--no-two-up-detection`
- `--marker-render-dpi`

## Compatibility

- The public `process_pdf` API remains compatible.
- Output remains one Markdown file per physical PDF page.
- Two-up pages contain ordered `## Logical Page N` sections.
- Existing `LayoutArtifact` serialization remains compatible.
- The extractor version changes to `0.3.0`, so old progress files are not resumed with the new pipeline.

## Verification

- Verification used local PyMuPDF and Marker only, with fallback disabled and no token-based service.
